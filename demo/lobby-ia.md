# 联机大厅 · 信息架构（IA）说明与三套布局原型对比

> 状态：**原型阶段**。三个原型页（`demo/lobby-plan-a/b/c.html`）只换布局、不换架构，
> 待负责人选定一套后，再动生产代码。本次交付**没有修改任何现有文件**
> （index.html / client.js / style.css / server.js 等一律未动）。

## 1. 现状与问题

- 现有联机入口 `#screen-join` 把「昵称 / 房间类型 / 房间号 / 进入游戏 / 公开房间列表」全塞在一张 560px 卡片里；
- 「排行榜」「对局回放」只是卡片底部 `#user-links` 的两行小字文字链接，不显眼；
- 待办③「挑战冠军」、待办④「光荣榜」上线后还要再挤两个入口，卡片必然爆掉。

因此先定 IA：**一级导航 5 项（全部是按钮）+ 右上角收纳 4 项（.btn.ghost 小按钮）**，再选布局。

## 5. 新增一个入口的步骤（以「赛季公告」为例）

**原型（本 demo）**：
1. 页内 `<script>` 的 `const NAV` 数组里追加一项
   （方案 A/B：取消数组末尾那行注释；方案 C：照抄 `announce` 那条的写法）；
2. 在 `<main>` 里加一个 `id="sec-announce"` 的 section；
3. 完成。导航按钮/胶囊/卡片、选中态、section 切换全部由循环生成，**页面结构不用改**。
   方案 C 的第 6 项「更多 → 赛季公告」就是按这个步骤真实加出来的，可直接点开验证。

**生产（迁移到 index.html 时）**：
1. 用选定的导航结构替换 `#screen-join` 里的入口与 `#user-links` 的小字链接；
2. index.html 里新增对应 section（或复用弹窗）；
3. client.js：把各入口接回现有函数（`joinGame` / `#link-leaderboard` / `/replay` 跳转）；
4. 新功能（挑战冠军 / 光荣榜）按待办③④实现后接回。

## 6. 三套方案取舍对比

### 方案 A：左侧竖向导航栏
**适合什么**：
- 入口还会持续增长——第 6、7、8 项都只是竖栏里多一行，竖栏自带滚动，天然可扩展；
- 希望所有入口同级、等宽、一眼扫完，点击成本一致；
- 想保留最接近现有「logo 居中大卡片」气质的过渡：右侧内容区就是一张放大的卡片。
**代价是什么**：
- 竖栏固定吃掉 150–210px 横向宽度，内容区在 844px 宽下只剩约 640px，表单只能纵向排，放不下并排大卡；
- 竖栏把 logo 压缩到 21px 小字（现有 44px），开场气场弱一档；
- 内容区是单列：排行榜/回放这类「列表型」内容很合适，但没有并排陈列「玩法入口」的空间。

### 方案 B：顶部胶囊导航 + 卡片网格
**适合什么**：
- 想同时给「扫一眼就能点」的胶囊 tab（定位状态）和「带说明的大卡片」（承载入口）两层导航；
- 入口 ≤ 6 个时最舒服：胶囊一行放得下，卡片一行 4 张；
- 「开始对局」用横向 hero 条，表单一行横排，「进游戏」路径最短。
**代价是什么**：
- 两层导航有重复感：胶囊和卡片都能去同一个地方，新用户可能困惑点哪边；
- 第 7 个入口出现时胶囊开始挤（844px 下尤其），需要再想收纳；
- 卡片一行 4 张：小屏时 desc 必须隐藏，卡片信息量缩水成「图标 + 标题」。

### 方案 C：左侧 hero 主按钮 + 右侧功能网格
**适合什么**：
- 「进入游戏」永远在视线左角、任何时刻一键可达——最像「大厅」而不是「导航页」；
- 右侧 2×2 网格 + 「更多」槽，天然给未来入口留位（第 6 项已演示）；
- 按钮层级最干净：全屏只有 1 个红色主按钮（hero 里的「进入游戏」）。
**代价是什么**：
- 「挑战冠军」被压在左栏 hero 下方，视觉权重比右侧网格里的「排行榜」还低——若它是下阶段主打玩法，这个位置吃亏；
- 右侧只有 2 列，放长名单（排行榜）时行高受限，长内容得滚动；
- 入口超过 7 个时「更多」槽会膨胀成二级抽屉，需要再设计。

## 7. 小屏（844×390，iPhone 横屏）下的行为与取舍

三套共用：**横向布局单套适配两个视口**（1280×720 与 844×390）；纵向允许滚动、**横向 0 溢出**；
矮屏（≤480px 高）自动压缩卡片留白与表单字号；`prefers-reduced-motion` 下动效全部归零。

- **方案 A**：竖栏收窄到 150px（15vw 下限），内容区 640px；矮屏下表单压缩为 16px 标题 + 小按钮，基本一屏放下。
  取舍：竖栏图标+文字仍全显，不缩成纯图标——保证可读，代价是内容区更窄。
- **方案 B**：logo 文字隐藏只留精灵球，胶囊保留全文字（5 个 tab ≈ 410px 放得下，图标隐藏）；
  hero 由横排折成「左标题行 + 表单两行」；四张卡缩成「图标 + 标题」横条。
  取舍：卡片 desc 被裁掉，信息靠胶囊 tab 文字补齐。
- **方案 C**：左栏收窄到 300px，hero 按钮改小并排；右侧网格仍 2 列，卡高压缩。
  取舍：左栏 hero + 挑战冠军卡在 390 高下几乎占满，右侧详情成为视觉主区。

## 8. 原型共守规则（三套一致）

- 只新建文件，不改任何现有文件；每个原型 `<link rel="stylesheet" href="../style.css">` 复用现有样式；
- 配色只用 style.css `:root` 变量（var()/rgba()），页内 `<style>` 无十六进制颜色字面量；
  唯一例外：精灵球的 `--bc:#e3350d;--band:#24303d`（照抄 index.html）；
- 动效 200–350ms、缓入缓出（cubic-bezier(.4,0,.2,1)），只动 transform / opacity / box-shadow / filter；
  含 `@media (prefers-reduced-motion: reduce)` 降级；
- 按钮层级：主 `.btn.primary` → 次 `.btn.secondary` → 再次 `.btn.ghost`；
  导航层「开始对局」与内容层「进入游戏」同为 primary（两级指向同一个动作）；
  方案 C 已把两者合并为 hero 里的「进入游戏」，是层级最简的形态；
- 纯静态、无网络请求、无外部资源；「光荣榜」为体面占位而非死链接。
