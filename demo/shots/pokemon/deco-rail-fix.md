## 一、改了什么（client.js）
1. **`buildDeco()` 布点排除 rail**：按 rail 的 `getBoundingClientRect()` **实时算**（宽度 CSS 是 `clamp(150px,15vw,210px)`，**没写死 150**），并把矩形**外扩 12px** 给漂浮动画留余量；同一颗球**最多重试 20 次**，仍越界就 `continue` **少放一颗**（绝不死循环/卡渲染）
2. **`fixDecoRail()`（布局后复测）**：`buildDeco()` 在**页面加载**时跑，那时大厅还是 `display:none`、rail 矩形量到 **0×0** → 排除判断等于空转（这是第一版实测 10/10=2 的真因）。所以在 `showScreen('lobby')`（四屏切换的**唯一中枢**）里挂一道复测：大厅一显示就用**真实矩形**把越界球**挪到 rail 右边界之外**（量不到就返回，不循环等待）

## 三、如实记的三件事
1. **第一版实测 10/10 = 2（失败）**：原因是 `buildDeco()` 跑在加载期、rail 无布局 → 已用 `fixDecoRail()` 补齐
2. **第二版实测仍 10/10 = 2**：这次是**装置测错了**——我在 stub 里直接改 `hidden` 显示大厅，**绕过了真实的 `showScreen('lobby')`**，钩子没被调用；改成走真实路径后 → 10/10 = 0 ✓
