# 璀璨宝石 · 宝可梦（Splendor Pokémon 桌游复刻）

用**纯原生 HTML / CSS / JavaScript** 制作的网页版桌游，复刻了韩国 Korea Boardgames 官方授权的
《璀璨宝石：宝可梦》核心玩法。支持**本地单机**和**局域网联机**，零第三方依赖。

## 🚀 如何运行

### 本地单机模式（一个人 / 热座 / 演示）

1. 双击打开 `index.html`（用 Chrome / Edge 浏览器）
2. 选择玩家：2-4 人，每位可以是人类、电脑·简单或电脑·困难
3. 选择目标分数，点击「开始游戏」

### 局域网联机模式（每人一台电脑）

1. 在一台电脑上打开命令行，进入本文件夹，运行：
   ```bash
   node server.js
   ```
   启动后会打印地址，例如 `http://192.168.1.4:3000`
2. 所有人都用浏览器打开这个地址（同一 Wi-Fi / 局域网）
3. **第一个加入的人自动成为房主**：可以添加电脑玩家、设置目标分、点「开始游戏」
4. 对局中：轮到你时才会显示行动按钮；断线的玩家轮到自己时 30 秒后自动跳过（可重连）

### 自动化测试

```bash
node sim.js 100 3 18    # AI 对战模拟：校验规则守恒与平衡性
node server.js          # 先启动服务器
node e2e-test.js        # 联机端到端回归测试（另开一个命令行窗口）
```

## 🎮 玩法速览

- **目标**：率先达到目标分数触发终局，完成当前一轮后分数最高者获胜
- **每回合五选一**：
  1. **拿取精灵球** — 拿 3 个不同颜色的球，或拿 2 个相同颜色的球（供应区该色 ≥4 个）
  2. **收服宝可梦** — 支付卡牌费用（已拥有的宝可梦提供永久加成自动抵扣），获得分数
  3. **预约宝可梦** — 收进预约区（最多 3 张）+ 获得 1 个**大师球**（万能球）
  4. **退还精灵球** — 把 1 个球退回供应区（防卡死的周转行动）
- **手牌上限**：精灵球（含大师球）最多 10 个
- 宝可梦分三阶：一阶（0~1分）、二阶（1~3分）、三阶（3~5分）

详细规则见游戏内的「规则说明」弹窗。

## 🏗️ 架构（面向未来部署）

```
浏览器(客户端)  ──POST 行动──►  服务器(Node)  ──SSE 推送状态──►  所有浏览器
   只负责渲染和操作           服务器权威：对局状态唯一        SSE 自动重连
```

- **服务器权威制**：对局状态只存在于服务器，客户端只发送行动、接收完整状态并渲染。以后部署到公网服务器时客户端一行都不用改
- **零依赖**：通信用 HTTP + SSE（Server-Sent Events）+ POST 实现，不需要 npm install，离线局域网可用；以后想换 WebSocket 只需改 `server.js`
- **代码三分离**：`game-core.js`（规则逻辑，浏览器/服务器共用同一份）、`client.js`（界面）、`server.js`（网络编排）
- **部署到公网**：把整个文件夹拷到云服务器，`node server.js` 即可（可在 config.js 改端口）

## 📁 文件结构

| 文件 | 说明 |
|---|---|
| `index.html` | 页面结构（本地设置 / 联机加入 / 大厅 / 游戏界面 / 弹窗） |
| `style.css` | 全部样式（纯 CSS 绘制的精灵球） |
| `config.js` | **🎛️ 数据配置：所有可调数值都在这里**（规则、AI、联机参数、80 张卡牌表） |
| `game-core.js` | 游戏核心逻辑（规则、AI、对局状态，浏览器/服务器共用） |
| `client.js` | 客户端（渲染 + 交互 + 本地/联机两种模式） |
| `server.js` | 联机服务器（静态文件 + 房间编排 + SSE 推送，`node server.js`） |
| `生成卡牌表.js` | 按费用模板批量重新生成卡牌表的工具（`node 生成卡牌表.js`） |
| `检查图片.js` | 卡牌图片命名检查工具，生成「图片命名对照表.txt」（`node 检查图片.js`） |
| `录入工具.js` + `录入工具.html` | **卡牌数值录入工具**：看图填数，一键写回 config.js（`node 录入工具.js`） |
| `sim.js` | AI 对战模拟测试（规则守恒 + 平衡性校验） |
| `e2e-test.js` | 联机端到端回归测试（需先启动服务器） |

## 🎛️ 如何调整数值

**所有数值都在 `config.js` 里，改完保存即生效（本地刷新浏览器 Ctrl+F5；联机需重启服务器）：**

- **改某只宝可梦的强度** → 找到卡牌表中它的那一行，直接改分数或费用，例如：
  ```js
  ['皮卡丘', 1, 0, 0, 0, 3, 0, 0, 'pink'], // 0分·费3
  //  名称     阶  分  红 蓝 黑 粉 黄  加成色
  ```
  把它改成 `1, 1, ...` 就是 1 分；把费用改成 `0,0,4,0,0` 就是费 4
- **加新宝可梦** → 复制一行，改名称和数值即可（牌堆自动变大）
- **改规则** → `RULES`：手牌上限、大师球数量、预约上限、目标分选项……
- **改 AI 强弱** → `AI_CONFIG`：思考时间、简单电脑乱走概率、困难电脑前期策略
- **改联机** → `NETWORK`：端口、断线跳过秒数、人数上限
- **整体重新平衡卡牌** → 修改 `生成卡牌表.js` 的费用模板，运行 `node 生成卡牌表.js`
  （⚠️ 会覆盖 config.js 里手工改过的卡牌数值）

## 🖼️ 卡牌图片（可选）

想给卡牌用上真实卡面图片（例如官方卡牌扫描件）：

1. **命名规则**：文件名 = config.js 卡牌表里的宝可梦名，放在 `pictures/` 文件夹，例如 `pictures/皮卡丘.jpg`
   ⚠️ 卡牌表里的名字必须**唯一**——官方版同一只宝可梦有多张卡（费用不同），重复的加后缀区分：
   `皮卡丘` 和 `皮卡丘2`，图片对应 `皮卡丘.jpg` 和 `皮卡丘2.jpg`
2. 运行 `node 检查图片.js`：生成「图片命名对照表.txt」（全部名字清单），并报告哪些已命名、缺失、多余
3. 图片加载成功会直接作为**卡面**显示；没有图片的卡牌自动退回程序绘制的样式——可以一张张慢慢补
4. **对齐官方数值**：如果卡面上印着官方费用/分数，对照着修改 config.js 卡牌表的对应行
   （每行 = 一张卡，可增删行让卡牌表与图片完全一致；改完建议跑 `node sim.js` 验证平衡）
5. 「稀有/传说幻兽」卡牌留给 v2（需要大师球捕获规则），先按宝可梦名命名备用

### 🎛️ 数值录入工具（推荐用它填卡牌数值）

```bash
node 录入工具.js    # 启动后浏览器打开 http://localhost:3100
```

- 每张卡一行：显示卡面大图（点击放大）+ 输入框（阶层 / 分数 / 五种球费用 / 加成色）
- 填过的行自动变绿，进度存在浏览器里，关掉重开不丢
- **💾 保存到 config.js**：一键把全部数值写回配置文件（名字自动锁定，防止和图片对不上）
- **🧪 模拟验证平衡**：跑 30 局 AI 对战检查死锁和守恒；显示「所有对局都无法结束」说明数值还没填完
