## 1. 验收口径（硬定义，先定死再开跑）

| 项 | 定义 |
|---|---|
| 对手 | **修复后的困难启发式 AI**（`game-core.js` v3.2.0 的 `chooseAIMoveDefault`），非 A 座位全部使用它 |

| 配置 | 目标分 **18**、人数 **2 / 3 / 4** |
| 达标 | 三档**同时** ≥ 80%（以评测种子集报数；独立种子集偏差 >5 个百分点则该项不认） |
| 报告格式 | 胜率 + 胜/总局数（例：`3人局 81.2%（406/500）`），同时报守恒违规数（必须为 0） |

**参照线（今天实测，500 局 / seed 20260915，全体同款困难 AI）**：

| 人数 | 座位 A 实测夺冠率 | 理论对称值 | 守恒违规 |
|---|---|---|---|
| 2 人 | 50.8% | 50.0% | 0 |
| 3 人 | 31.8% | 33.3% | 0 |
| 4 人 | 29.2% | 25.0% | 0 |

→ 说明：4 人局 A 座实测高于 25%，500 局抽样误差约 ±2 个百分点。

> **2026-09-17 更正（秉心）**：上面「存在座位/先手效应」的推断**是错的**——那是 **500 局**的噪声（ 1σ≈2.2 点）。用 **5000 局**重测后，座位间差异消失：

> - 结论：**先手优势 ≤ 噪声水平**（全部位置差 ≤1.8 点，多数 ≤1 点）；4 人局是对称的 25/25/25/25。榜单与难度设计**不需要做先手补偿**。

## 9. ppo-agent 学习率调度 A/B（2026-09-17 新增）

对照"随训练进度衰减到初始 10%"这套调度是否真的有用：

| 臂 | 命令 | 语义 |
|---|---|---|
| **decay10（缺省）** | 不传，或 `--lr-schedule decay10` | 前端学习率随本段训练进度线性衰减到初始值的 `--lr-decay-to` 倍（缺省 0.1：α 3e-3→3e-4、β 1e-2→1e-3；传 0 = 一路衰减到 0） |
| 不衰减 | `--no-lr-decay` | 恒为前端值（缺省 3e-3 / 1e-2） |
| 无学习对照 | `--lr-schedule front-zero` | 前端值强制 0 → 全程学习率 0（权重不动，验证"学习/衰减"是否真的发生） |

参数细则：

- `--alpha-front`（缺省 3e-3）/ `--beta-front`（缺省 1e-2）：前端（起始）学习率。只显式传 `--alpha`/`--beta` 时，以它们为前端值（旧命令行行为不变）；都没传时前端 = 3e-3 / 1e-2。
- `front-zero` 与显式 `--alpha-front`/`--beta-front` **互斥**（报错）；与 `--alpha`/`--beta`/`--no-lr-decay` 兼容（被覆盖/无效果）。
- `--lr-decay-to <比例>`（缺省 0.1）：decay10 的衰减底线，取值 0~1，终点 = 前端值 × 该比例。0.1 = 旧行为（衰减到 10%），0 = 一路衰减到 0（后段学习率归 0、训练停摆，只作对照臂用）。`--no-lr-decay` 与 `front-zero` 下不生效（无衰减/恒 0），照常落档。
- 调度生效参数（模式、前端值、衰减终点、衰减底线比例）写进所有权重文件的 `meta` 与 `data/` 摘要：`lrSchedule` / `alphaFront` / `betaFront` / `alphaEnd` / `betaEnd` / `lrDecayTo`。

## 10. ppo-agent 评估座位（--eval-seats / --str-weights，2026-09-17 新增）

AI 对打评估：评估时每个座位指定用哪个 AI，替代"固定座位 0 贪心 vs 全启发式"的旧口径。

| 座位 token | 用什么 AI |
|---|---|
| `str` @ 座位 0 | **被测策略**：`--eval-only` 的文件 / 训练中的当前模型（贪心） |
| `str` @ 座位 ≥1 | `--str-weights` 指定的文件（缺省 = 与被测策略同网，即自对弈） |
| `def` | 困难启发式 AI（`chooseAIMoveDefault`） |
| `rand` | 随机合法动作（走游戏种子 RNG，同 seed 逐位可复现） |

规则：

- `--eval-seats` 缺省 = `['str','def',...]`（旧行为不变：贪心 vs 启发式）；列表长度 ≤ `--players`，不足自动补 `def`，超长报错。
- 训练模式主指标 = **座位 0 的胜率**；座位 0 非 `str` 时评估不测学习者（本轮不参与最优判定，日志注明），历史最优仍按座位 0 口径比较。
- `--eval-only` 模式落档 `weights/<权重名>.eval-<座位>[.vs-<对打权重>].json`：分座位胜率 / 平均分 / 平均进化、逐局记录、被测与对打权重的 **sha256 指纹**；同名重跑覆盖（口径不变时可复现复核）。
- 评估曲线的座位口径写进每条 `evalCurve` 与 summary（`evalSeats`）；`--resume` 时曲线座位口径与本次不同会打注意提示（前后曲线对比口径不同）。
- **预设名 `mirror`（2026-09-19 新增）**：`--eval-seats mirror` 按 `--players` 自动展开成全 `str` —— p2→`[str,str]`、p3→`[str,str,str]`、p4→`[str,str,str,str]`，就是§12 的**镜像线**。展开结果与手写 `str,str,…` **逐位一致**（连产物文件名都一致，重跑会覆同名档）。预设只能**整条单独用**，`str,mirror` 这类混写直接报错。显式写法与缺省行为都**不变**（不传 `--eval-seats` 仍是 `[str,def,…]`）。

典型命令：

```bash
# 对称性参照线：3 个启发式 AI 互打
node 工具/rl/ppo-agent.js --eval-only weights/ppo-agent-p3-R2p3-best.json --players 3 --eval-seats def,def,def
# 常规评测（= 缺省行为）
node 工具/rl/ppo-agent.js --eval-only weights/ppo-agent-p3-R2p3-best.json --players 3 --eval-seats str,def,def
# 双模型对打：A（被测）vs B（--str-weights）vs 启发式
node 工具/rl/ppo-agent.js --eval-only weights/ppo-agent-p3-R2p3-best.json --players 3 --eval-seats str,str,def --str-weights weights/ppo-agent-p3-B-best.json
# 自对弈 + 座位效应：同网坐两个座位
node 工具/rl/ppo-agent.js --eval-only weights/ppo-agent-p3-R2p3-best.json --players 3 --eval-seats str,str,def
# 训练中换评测口径：座位列表不足自动补 def
node 工具/rl/ppo-agent.js 200 100 --players 3 --eval-games 100 --eval-seats str,def,def
```

## 11. ppo-agent 对手池快照节奏与上限（--snapshot-every / --pool-recent，2026-09-17 新增）

对手池 = 2 个固定对手（heuristic / random）+ 训练中定期入池的 θ 快照（greedy 网）。旧行为写死「每 2000 局入池、快照区最多 12 个」→ 跑满 5000 局池也到不了上限，长跑（10 万局量级）才会碰到 14 的上限；现在两个都参数化：

| 参数 | 缺省 | 语义 |
|---|---|---|
| `--snapshot-every <n>` | 2000 | 每 n 局把当前 actor 快照写入对手池（正整数） |
| `--pool-recent <K>` | 0 | 快照区上限：0 = 旧行为（快照区最多 12，池上限 14 = 2+12）；K > 0 = 每次入池后裁剪快照区**只留最近 K 个**（2 个固定对手不裁，池上限 = 2+K） |

规则：

- K=0（缺省）时行为与旧版逐位一致；K>0 时旧上限 14 不生效，池上限 = 2+K。
- 快照名 `snapN` 编号只增不减（裁剪不重编号）；`--resume` 恢复时按池内最大编号续编，不会重号。
- 两个参数都写进权重文件 `meta` 与 `data/` 摘要：`snapshotEvery` / `poolRecent`。

典型命令：

```bash
# 旧行为对照：每 500 局入池、快照区上限 12（3000 局 → 池 2+6=8）
node 工具/rl/ppo-agent.js 3000 1000 --players 2 --eval-games 100 --snapshot-every 500 --tag POOLDEF
# 新行为：每 500 局入池、快照区只留最近 2 个（3000 局 → 池恒 2+2=4）
node 工具/rl/ppo-agent.js 3000 1000 --players 2 --eval-games 100 --snapshot-every 500 --pool-recent 2 --tag POOLFIX
```

### 12.5 线上只读怎么建隧道（`human-bench`）

一段可复制命令（占位符 `<>` 自己填；密钥靠 `~/.ssh/config` 的 Host 别名或环境变量指定的私钥，**不写进命令行**）：

```bash
# 1) 建隧道：本机 <本地端口> → <跳板/主机> 上的 MySQL 3306（-N = 不跑远端命令）
ssh -N -L <本地端口>:127.0.0.1:3306 -o ServerAliveInterval=30 -o ExitOnForwardFailure=yes -o ConnectTimeout=10 <跳板/主机>

# 2) 另开一个终端跑尺子（连本地端口；连线上必须显式 --db prod）
#    口令走环境变量 SPLENDOR_DB_PASSWORD（或 data/db.json），命令行只传非敏感项
node 工具/rl/human-bench.js --db prod --db-host 127.0.0.1 --db-port <本地端口> --db-name <库名> --report 工具/rl/data/human-report.json

# 3) 用完回收隧道（别让它在后台挂着）
#    前台跑的：Ctrl+C ｜ 后台跑的：taskkill /PID <ssh 的 PID> /F（Windows）/ kill <ssh 的 PID>（Linux/macOS）
```

纪律（写死在 `human-bench.js` 里）：**服务器不落文件**（全程不写远端磁盘、快照只落本地 `工具/rl/data/`）、**只读会话**（只发 SELECT，连上立刻 `SET SESSION TRANSACTION READ ONLY`；`--readonly-selftest` 会当场试一条写来证明写真的被挡）、**用完回收隧道**。
